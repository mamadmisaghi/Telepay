# TelePay — وضعیت آمادگی برای استقرار

آخرین تغییر: ۲۶ سپتامبر ۲۰۲۶

## تصمیم‌های نهایی

- نام TelePay؛ توکن Tele با تیکر TELE.
- پسوند اجباری همهٔ mintها: **TeLe**، دقیقاً با همین حروف.
- ۸۰٪ کارمزد واقعاً دریافت‌شده برای یوزرنیم تلگرام؛ ۲۰٪ پروژه.
- مالکیت موجودی بر اساس **یوزرنیم** است. صاحب جدیدِ یوزرنیم می‌تواند موجودی هنوز رزرو یا Claim‌نشده را دریافت کند. سازنده فقط نام کاربری را وارد می‌کند؛ ID گیرنده لازم نیست.
- هر Claim تازه، ورود مجدد معتبر تلگرام با اثبات حداکثر دو دقیقه‌ای می‌خواهد. ID داخلی فقط برای نشست و تأیید کیف پول استفاده می‌شود.

## کارهای ساخته‌شده

| بخش | پیاده‌سازی فعلی |
| --- | --- |
| هویت | Telegram OIDC، PKCE، state متصل به مرورگر، بررسی امضای JWT، issuer، audience، expiry و nonce |
| کیف پول | Phantom و Solflare، امضای پیام مخصوص دامنه و تأیید یک‌بارمصرف در سرور |
| دیتابیس | PostgreSQL، جداول لانچ، یوزرنیم، موجودی، دریافت کارمزد، Claim و صف تراکنش |
| لانچ | متادیتا و تصویر، Pump SDK، خرید اولیه، شبیه‌سازی، امضای کاربر، تطبیق دقیق پیام و امضای mint |
| پسوند | تولید Ed25519 بومی، مخزن رمزگذاری‌شدهٔ TeLe، رزرو اتمیک و جلوگیری از استفادهٔ دوباره |
| کارمزد | دریافت از Pump/PumpSwap، انتقال به خزانه، ثبت دریافت نهایی و تقسیم صحیح ۸۰/۲۰ |
| Claim | رزرو اتمیک موجودی، درخواست تکرارپذیر، ثبت تراکنش پیش از ارسال و تطبیق پس از timeout |
| رابط واقعی | ورود، کیف پول، لانچ، Claim، توکن‌ها، پروفایل، آمار و رسیدهای واقعی؛ وضعیت خالی و خطا |
| VPS | خروجی مستقل وب، Docker، PostgreSQL، Caddy/HTTPS، health check، پشتیبان‌گیری و بررسی پیش‌نیازها |

نسخهٔ جدید Sites محیط Devnet مستقل دارد: ساخت واقعی توکن و خرید اولیه، تأیید یوزرنیم از طریق TelePayFunBot، شارژ شفاف کارمزد شبیه‌سازی‌شده و پرداخت واقعی Devnet. مسیر VPS همچنان API/PostgreSQL و ورود OIDC جداگانه دارد؛ اتصال همان بات به مسیر VPS قبل از انتقال لازم است. گزارش جاری آزمون‌ها و موارد باقی‌مانده در `deploy/READINESS.md` ثبت شده است.

## وضعیت لوگو

بازسازی تصویریِ نسخهٔ شفاف همچنان لبه‌های نامنظم تولید کرد. طبق اصلاح نهایی کاربر، همان نسخهٔ شفاف سفید و آبی بدون هیچ پس‌زمینهٔ آبی در هدر، سایر نقاط و آیکن مرورگر استفاده می‌شود. فرم T همان دارایی انتخاب‌شده است؛ خروجی بازسازی ناموفق جایگزین نشده است.

## اعتبارسنجی انجام‌شده

آزمون‌های محاسبات، حسابداری با PostgreSQL داخل PGlite، تغییر صاحب یوزرنیم، درخواست هم‌زمان، تکرار درخواست، آزادسازی پرداخت ناموفق، CSRF، امضای کیف پول، state تلگرام، تغییر پیام تراکنش و بازیابی ارسال نامشخص اجرا می‌شوند. کلیدها و RPC در این آزمون‌ها آزمایشی‌اند؛ پول واقعی ارسال نشده است.

بیلد وب مخصوص VPS و بررسی TypeScript اجرا شده‌اند. تست واقعی Docker/PostgreSQL، ورود تلگرام و تراکنش Pump روی شبکه هنوز انجام نشده‌اند؛ این محیط Docker ندارد و اطلاعات اتصال واقعی پروژه هم ارائه نشده است. بنابراین عبارت «آمادهٔ استقرار و اتصال» صحیح است؛ «محصول مالی کاملاً تست‌شده روی شبکه» هنوز صحیح نیست.

## آنچه اکنون لازم است

۱. VPS لینوکس و دامنه با دسترسی DNS؛ روی سرور runtime و پایگاه داده نصب می‌شوند.
۲. Client ID و Secret ورود تلگرام از BotFather و ثبت callback دامنه.
۳. RPC سولانا و دو کیف پول مجزا برای خزانه و هزینهٔ تراکنش‌ها؛ کلیدها فقط در secretهای سرور وارد شوند.
۴. تولید مخزن TeLe روی سرور، بررسی سلامت، تست ورود، لانچ کنترل‌شده، دریافت کارمزد و Claim کوچک.
۵. تست بازیابی پشتیبان، restart و هم‌زمانی روی PostgreSQL واقعی، سپس فعال‌کردن سرویس عمومی.

مقادیر حداقل Claim و آستانهٔ جمع‌آوری فعلاً تنظیمات اجرایی قابل تغییرند، نه توکنومیکس نهایی. برداشت خودکار سهم پروژه فعال نیست. نمودار قیمت و معاملهٔ داخلی در این نسخه ساخته نشده‌اند؛ آمار کارمزد واقعی نمایش داده می‌شود و معامله به Pump.fun لینک دارد.
